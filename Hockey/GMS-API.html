Overview

GMS-API is a small JSON API that mirrors the fixtures, results and league standings for Chelmsford Sports Club's hockey teams. It's built and run by the club's IT volunteers, and it's free for anyone connected to the club to use — for a display screen in the clubhouse, a personal project, or anything else.

Base URL: https://gms-api.chelmsfordsc.org.uk

Every endpoint below is a GET request over HTTPS and returns JSON. There's nothing to install and no SDK — any language or tool that can make an HTTPS request and read JSON will work, including a browser's own fetch().

Getting an API Key

Every request needs an API key. Email it@chelmsfordsc.org.uk with a line or two about what you're building, and we'll send you a key. There's no cost and no formal approval process — this is just so we know who's using it and can let you know if anything changes.

Using your key

Send it on every request as an X-API-Key header:

X-API-Key: YOUR_API_KEY
Keep your key out of any code you publish publicly (a public GitHub repo, a client-side script anyone can view the source of, etc.). If you think a key has leaked, email us and we'll issue you a new one.

GET /api/today

GET /api/today

Returns fixtures and results scheduled for today only. Useful for a "what's on today" display without having to filter the full fixture list yourself.

Parameters

None.

Example request

# curl
curl -H "X-API-Key: YOUR_API_KEY" \
  https://gms-api.chelmsfordsc.org.uk/api/today
// JavaScript (fetch)
const res = await fetch('https://gms-api.chelmsfordsc.org.uk/api/today', {
  headers: { 'X-API-Key': 'YOUR_API_KEY' }
});
const data = await res.json();

Example response

{
  "fixtures": [
    { /* same shape as /api/fixtures below */ }
  ]
}

Same field shape as /api/fixtures below, filtered down to just today's date — an empty array simply means nothing's on today.

GET /api/fixtures

GET /api/fixtures

Returns every known fixture and result across Chelmsford's hockey teams and the competitions they play in — past, present and future. Optional query parameters narrow this down.

Parameters

NameInDescription
teamQuery stringOptional. A club_team_id (see /api/teams) — returns only fixtures involving that Chelmsford team.
comp_idQuery stringOptional. A competition ID (see /api/leagues) — returns only fixtures in that competition.
from / toQuery stringOptional. ISO dates (YYYY-MM-DD), inclusive, filtering on the fixture's date. Combine both for a range, or use either alone for an open-ended one.

All filters can be combined — e.g. ?team=47e1e6e9-120c-4185-ad68-be7b70b76eac&from=2026-09-01. Leave all of them off to get everything, as before.

Example request

# curl -- everything
curl -H "X-API-Key: YOUR_API_KEY" \
  https://gms-api.chelmsfordsc.org.uk/api/fixtures

# curl -- just one team, from today onward
curl -H "X-API-Key: YOUR_API_KEY" \
  "https://gms-api.chelmsfordsc.org.uk/api/fixtures?team=47e1e6e9-120c-4185-ad68-be7b70b76eac&from=2026-09-18"
// JavaScript (fetch)
const res = await fetch('https://gms-api.chelmsfordsc.org.uk/api/fixtures', {
  headers: { 'X-API-Key': 'YOUR_API_KEY' }
});
const data = await res.json();

Example response

{
  "fixtures": [
    {
      "fixture_id": "19_sep_2026_upminster_3_chelmsford_4",
      "comp_id": "e28a25be-e7df-41b2-a923-a5c2921c0ca6",
      "home_team_name": "Upminster 3",
      "away_team_name": "Chelmsford 4",
      "fixture_date": "19 Sep 2026",
      "fixture_date_iso": "2026-09-19",
      "fixture_time": "11:30",
      "status": "scheduled",
      "home_score": null,
      "away_score": null,
      "scorers": null,
      "venue_name": "Coopers Company & Coborn School",
      "venue_url": "https://www.google.com/maps/search/?api=1&query=Coopers+Company+%26+Coborn+School",
      "club_team_id": "47e1e6e9-120c-4185-ad68-be7b70b76eac",
      "club_side": "away",
      "last_updated": "2026-09-17T17:39:41.899Z"
    }
  ]
}

Field reference

FieldDescription
fixture_idStable unique ID for this fixture, derived from its date and team names. Use it with /api/fixtures/:id.
comp_idID of the competition this fixture belongs to, or null if not yet known. See /api/leagues.
home_team_name / away_team_nameTeam names as published by the league.
fixture_dateDate as the league displays it, e.g. "19 Sep 2026". Not sortable/comparable as text — use fixture_date_iso instead.
fixture_date_isoThe same date in YYYY-MM-DD form, for sorting or the from/to filters above.
fixture_timeKick-off time as text, e.g. "11:30" (or "TBC"). null once the match has been played (see status).
status"scheduled" until the match has been played, then "completed".
home_score / away_scoreFinal score once status is "completed", otherwise null.
scorersGoalscorer information, or null if not available.
venue_name / venue_urlWhere it's being played, with a link to a map where one is known.
club_team_id / club_sideOnly populated when Chelmsford is playing in this fixture — which of our teams it is, and whether we're "home" or "away".
last_updatedWhen this row was last refreshed from the league's own system, as an ISO timestamp.

}

GET /api/teams

GET /api/teams

Lists Chelmsford's own hockey teams as the API currently knows them, along with the club_team_id used to filter /api/fixtures by team.

Parameters

None.

Example request

# curl
curl -H "X-API-Key: YOUR_API_KEY" \
  https://gms-api.chelmsfordsc.org.uk/api/teams

Example response

{
  "teams": [
    {
      "club_team_id": "47e1e6e9-120c-4185-ad68-be7b70b76eac",
      "team_name": "Chelmsford 4",
      "fixture_count": 22,
      "last_seen": "2027-03-20"
    },
    {
      "club_team_id": "09083ed3-cd42-4c8a-9cd1-0813729badb8",
      "team_name": "Chelmsford 5 (F)",
      "fixture_count": 18,
      "last_seen": "2027-03-06"
    }
  ]
}

Field reference

FieldDescription
club_team_idStable ID for this team. Use it as ?team= on /api/fixtures.
team_nameTeam name as most recently seen from the league (may or may not carry a gender suffix like "(F)" depending on which league page it was last seen on).
fixture_countHow many fixture rows the API currently has for this team.
last_seenThe latest fixture_date_iso we have for this team (i.e. the date of its last known fixture, played or upcoming).

Only teams the pipeline has actually seen play (home or away) are listed — a brand new team won't appear here until its first fixture has been picked up.

GET /api/leagues

GET /api/leagues

Self-serve lookup for competition IDs — no need to email us for a comp_id any more. Only lists competitions one of Chelmsford's own teams is actually registered in, and grows automatically as new teams/seasons are picked up.

Parameters

NameInDescription
searchQuery stringOptional. Case-insensitive substring match on the competition name. Omit to list everything.

Example request

# curl -- everything
curl -H "X-API-Key: YOUR_API_KEY" \
  https://gms-api.chelmsfordsc.org.uk/api/leagues

# curl -- search by name
curl -H "X-API-Key: YOUR_API_KEY" \
  "https://gms-api.chelmsfordsc.org.uk/api/leagues?search=Women"

Example response

{
  "leagues": [
    {
      "comp_id": "255273c5-c270-4304-b396-cc1b911a5754",
      "name": "East Women's Division 2 South East",
      "season": "2026-2027",
      "gender": "F"
    },
    {
      "comp_id": "b69e5afd-30e5-484c-b8a9-f5ca0cf010c0",
      "name": "East Women's Premier Division",
      "season": "2026-2027",
      "gender": "F"
    }
  ]
}

Field reference

FieldDescription
comp_idUse this with /api/leagues/:comp_id, /api/standings, or as ?comp_id= on /api/fixtures.
nameCompetition name as published by the league.
seasonSeason string, e.g. "2026-2027".
gender"M", "F", or null if not determinable from the name.

GET /api/standings

GET /api/standings?comp_id=

Returns the league table for a single competition.

Parameters

NameInDescription
comp_idQuery stringRequired. The competition's ID — see /api/leagues to look one up by name.

Example request

# curl
curl -H "X-API-Key: YOUR_API_KEY" \
  "https://gms-api.chelmsfordsc.org.uk/api/standings?comp_id=255273c5-c270-4304-b396-cc1b911a5754"

Example response — no matching data

{
  "standings": []
}

The response is always an object with a standings array, empty when there's no data for that comp_id yet.

Example response — populated

{
  "standings": [
    {
      "team_name": "Chelmsford 4",
      "position": 1,
      "played": 4,
      "won": 3,
      "drawn": 1,
      "lost": 0,
      "goals_for": 12,
      "goals_against": 3,
      "goal_difference": 9,
      "points": 10
    }
  ]

One entry per team in the competition, ordered by league position. Field names match the columns written by our own scraper, so they're accurate — the specific numbers above are illustrative rather than a live-pulled example; happy to swap in a real one if you send us a response from a populated comp_id.

GET /api/status

GET /api/status

A simple health-check — confirms the API is up and returns the single most recent scrape log entry, so you can see when the underlying data was last refreshed (and whether that last refresh succeeded).

Parameters

None.

Example request

# curl
curl -H "X-API-Key: YOUR_API_KEY" \
  https://gms-api.chelmsfordsc.org.uk/api/status

Example response

{
  "last_scrape": {
    "id": 1657,
    "show_type": "matchdays",
    "club_id": null,
    "comp_id": "b69e5afd-30e5-484c-b8a9-f5ca0cf010c0",
    "status": "success",
    "message": "...",
    "run_at": "2026-09-18T18:24:41.178Z"
  }
}

status on the inner object is one of "success", "empty" (ran fine, nothing new), "skipped" (e.g. a stage lock was already held), or "error".

GET /api/status/history

GET /api/status/history

Like /api/status, but returns a run of recent scrape log entries instead of just the latest one — handy for spotting a pattern (e.g. a cluster of errors) without needing direct database access.

Parameters

NameInDescription
limitQuery stringOptional. How many entries to return, most recent first. Defaults to 20, capped at 100.

Example request

# curl
curl -H "X-API-Key: YOUR_API_KEY" \
  "https://gms-api.chelmsfordsc.org.uk/api/status/history?limit=10"

Example response

{
  "history": [
    { /* same shape as the inner object in /api/status above */ },
    { /* ... */ }
  ]
}

Errors

Errors come back as JSON with a normal HTTP status code:

StatusMeaningExample body
401 Missing or incorrect X-API-Key header. {"error": "Unauthorized"}
429unverified Too many requests in a short space of time — see Rate Limits. (Confirmed correct by code inspection; we haven't yet actually tripped this limit against a real key to see it live.) {"error": "Too many requests"}

Rate Limits

This API runs on a free hosting tier, so there's a limit on how many requests it accepts from any one key or address in a short period. Normal use — a page that refreshes every so often, a script that checks in occasionally — will never come close to it.

If you're building something that needs to call the API very frequently (many times a minute, for lots of users), please email it@chelmsfordsc.org.uk first so we can make sure it'll work smoothly for everyone.
